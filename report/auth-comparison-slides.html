1 · 인증/인가 방식1안 자체 JWT

자체 인증 서버가 토큰을 발급하고 클라이언트가 직접 보관

  • 로그인 상태: 세션 방식과 토큰 방식 중 하나를 직접 설계합니다. 이벤트유 방식은 토큰 방식입니다.
  • Access Token: JWT를 직접 생성하고, 각 서비스가 서명과 exp를 검증합니다.
  • Refresh Token: 저장, 만료, 재발급, Rotation, 폐기 정책을 모두 직접 구현합니다.
  • 토큰 저장 위치: 클라이언트 보관 방식(Storage 또는 Cookie)과 서버 측 저장소(Redis/DB) 사용 여부를 직접 결정합니다.
특징: 구조가 단순하고 자유도가 가장 높습니다. 대신 표준 프로토콜(OAuth2/OIDC)이 제공하는 보안 장치(PKCE, 표준 Revocation 등)도 필요하면 직접 만들어야 합니다.
AT = Access Token, RT = Refresh Token

2 · 인증 절차 커스텀2FA

2안 SAS✔ 테스트 완료

  • Spring Security 7.1의 @EnableMultiFactorAuthentication과 One-Time Token 로그인 조합

  • AT TTL 단축, 장기 로그인 유지는 RT로 처리
  • Opaque Token + Introspection으로 전환 (요청마다 조회. 이번 조사에서는 구현하지 않음)

Direct Access Grant(ROPC)는 OAuth 2.1에서 제외되고 Authentication Flow(2FA)를 우회하므로 대안으로 적합하지 않습니다.
